Background, Task Contract, and Scoring Methodology

VeriBench evaluates autonomous software verification end-to-end: given a public Python reference module and five explicit input/output examples, an agent outputs a self-contained Lean 4 development containing executable code, unit/property checks, formal pre-/postconditions and behavioral specifications, and complete kernel-checked proofs. All scoring rejects sorry, added axioms, and theorem-level native_decide, requiring transitive proof axioms to remain strictly within Lean's standard core triple {propext, Classical.choice, Quot.sound}.

Conjunctive Metric Acronyms (Expanded)

  • HCSCv (Harsh Conjunctive Semantic Consistency verified): Binary {0, 1} per-task pass. Requires compiling code, valid tests (IC_tests = 1), all theorems proved cleanly in Lean (IC_proofs = 1), reference consistency (RC_tests, RC_proofs), and Formal Specification Coverage (FSC) simultaneously.
  • SCSCv (Smooth Conjunctive Semantic Consistency verified): Continuous [0, 1] aggregate score giving graded credit on incomplete specs while collapsing to 0 if any hard gate fails.
  • int_ref vs int: int_ref enforces hidden external reference checks (RC_tests, RC_proofs) in addition to internal consistency and FSC; int evaluates internal consistency and FSC alone.

Execution Modes & Checker Types

  • DT (Differential Testing) vs no DT: Under DT, the compiled Lean function is executed against Python across hundreds of randomized and boundary cases so compilation with silent semantic drift is caught immediately.
  • Lean-checked non-vacuous entailment vs 2-LLM coverage reading: On vb-priv, coverage is verified by proving Agent.FS -> GoldRef.FS inside Lean alongside explicit vacuity and satisfiability checks. Legacy 2-LLM coverage readers disagreed with Lean proofs on 27/211 and 38/211 tasks, explaining why Harsh int_ref jumped from 1/214 (0.47%) to 50/214 (23.36%) under formal Lean checks.

FSC Prover & Differential-Testing Validation (Experiment 171 & 11-06 Replay)

FSC is a one-sided ruler. A passing check requires a Lean-compiled proof with standard axioms only, a non-vacuous and satisfiable agent specification, and every gold theorem proved — so reported coverage is a verified lower bound on true coverage, and a failure denotes not verified rather than definitively non-covering.

Prover Sensitivity & False-Acceptance Controls (veribench Exp 171)

  • Gold proves itself: 256/256 (95% Wilson CI [98.5%, 100%]) after fixing 6 generator bugs.
  • Sensitivity on known-true rewrites (P_D): 132/132 part B [97.2%, 100%] across both verified prover families and 334/334 part C [98.9%, 100%].
  • False acceptance on Lean countermodel-certified false specs (P_F): 0/124 part B [0%, 3.0%] and 0/375 part C [0%, 1.0%] (0/499 total; 95% upper bound 0.8%).
  • Vacuity & satisfiability gates: 0/72 vacuous specs accepted; 0/72 contradictory specs accepted once the satisfiability check runs.
  • Dose-response & stability: Tracks kept gold fraction k/n across 126 specs (Pearson r=0.77, Spearman rho=0.78, never below k/n); test-retest verdict agreement 95/100 (kappa=0.90).

Miss Rate, Multi-Prover Recovery & 11-06 DT Replay

  • First-prover miss rate: An audit of 72 failures found 42/72 (58% [47%, 69%]) were true-covering specs the first prover missed. Adding a second proprietary prover raised verified coverage on n=1,024 runs from 66.1% to 84.3% (manual inspection measured 3.3% unfaithful/unclear passes on second-prover recoveries).
  • Expert-rating validation split: Across 75 off-format human-rated artifacts (25 tasks: 10 train / 5 validation / 10 test), faithfulness-filtered prover pass vs mean human score shows Spearman 0.14 (off-format transfer result).
  • 11-06-2026 Private DT Replay: Losslessly replayed all 214/214 saved private tasks across 87,714 test cases (642/642 compiler/execution processes succeeded), establishing finite executable agreement without recomputing historical aggregates.

Approved Public Worked Example: Gregorian day_of_year

We do not release held-out task identifiers, prompts, or per-task scores. To make the specification gap concrete without leaking private items, consider the approved calendar illustration from our public note: 

A year is a leap year when it is divisible by 4, except that a
year divisible by 100 is a leap year only when it is also
divisible by 400.

day_of_year(year, month, day) returns the ordinal of a valid
date within its year: January 1 has ordinal 1 and every later
day of the same year has the ordinal of the previous day plus one.

day_of_year raises ValueError when the date is not valid.

A Lean theorem stating only 1 <= day_of_year y m d <= 366 compiles cleanly and passes randomized differential tests, yet leaves the specification nearly empty. Full credit requires encoding successor monotonicity, inverse round-trip consistency with ordinal_to_date, exact Gregorian century leap-year rules, and explicit domain rejection. On vb-priv, 23.36% Harsh vs 0.867 Smooth measures precisely this gap.

Scope, Disclosure Constraints, and Threats to Validity

  • Separate Harnesses and Efforts: We never pool agent harnesses or reasoning efforts into a single row. Public 896 frontier rows reflect both the underlying model and its agent loop (Terminus 2 with 14,400s cap vs Claude Code and Codex CLI with 3,600s cap; Pi 1.4.0 for open-weight models).
  • Telemetry Missingness: Cost, token, and latency fields are shown strictly where directly logged: vb-priv telemetry comes from Valkyrie Exp 16 (n=79 Opus 5.5 cost/duration, n=76 main tokens; n=15 GPT-6 Astra telemetry slice where full-214 accuracy is unmeasured); Claude Code and Codex CLI runs on Public 896 did not record cost/token ledgers; the 9th internal pre-release model from Exp 109 is withheld per Vals policy.
  • Unrecomposable Historical Aggregates: On vb-priv, historical DT applied to 209/214 tasks; the 11-06 replay checked 214/214 executable agreement (87,714 cases) without altering the baseline aggregate. On Public 896, Exp 172 (Qwen3-Coder-30B-A3B-FP8 + gemini-3.1-pro-preview judge) uses a different test gate (IC_tests=H) and judge and is flagged separately from Sonnet-judged rows.
